# BioHub 本轮暴露问题与修复计划

日期：2026-10-22。范围：本次 CCA0737S0009 续跑所暴露的软件问题；本文是修复方案，不代表这些修复已经实施。Word／PDF 报告继续暂缓。

## 结论

确实还有问题。本轮能够交付 23 项已核验分析，是软件原生执行、额外编写的续跑脚本、原作业恢复、独立数据验证和单独结果打包共同完成的，不能据此认定桌面软件已经具备完整的一键恢复、一键验收能力。

最需要修复的是三件事：**结果补回后软件状态仍不一致；提交回执不足以支持浏览器重启恢复；源码修复没有完整进入已检查的发布目录。** 网页归档也没有彻底解决，仍有 4 个原网页处于 partial。

这里将“数据有效”“图表可见”“原网页归档完整”“附件完整”分别验收。静态整理页能打开，不代替原网页验收；文件哈希相同，不代替数据与输入的关联验证。

## 三、具体修复方案

### A. 作业回执与恢复

1. 提交前原子记录：节点、输入 SHA-256、参数摘要、站点、尝试编号、动作意图。
2. 捕获成功回执：job ID／RID、结果 URL、提交时间、浏览器归属、可用的原站查询凭据。敏感会话凭据留在受保护的本地存储，不进入可分享结果包。
3. 状态分为 `prepared → submitting → receipt_known → running → results_ready`；点击超时且没有回执进入 `needs_reconciliation`。
4. 恢复先检查原页面、持久回执和站点查询能力。有作业号则查询原作业，不能回到首页自动重提。
5. 原站不支持幂等或查询时，不能承诺绝对“恰好提交一次”。保留不确定状态，并提供核对回执或明确新建作业的入口。
6. 分开处理页面读取失败、模型不可用、远端分析失败、文件下载失败；文件下载失败不回退为重新分析。

验收：提交后立即关闭 Chrome、关闭软件、终止后台，重启仍能定位原作业；有回执的恢复全程不触发提交。无回执的中断不得自动再次点击提交。

### B. 统一结果状态与科学验证

1. 执行历史和结果有效性分开保存。原执行失败可以保留；后来补回并验证的结果可成为当前有效结果。
2. 外部导入必须绑定节点、输入指纹、参数、来源及文件清单，由引擎内置验证器产生结论，不接受调用方直接写 `verified: true`。
3. 从本轮脚本迁移 BLAST XML、InterPro 序列与位置、Musite 位点、HMMER 命中、MAFFT 序列一致性、ESPript 输入、树叶与比对、PrankWeb 模型关联等验证。
4. 验证记录绑定文件内容指纹、验证器版本、输入与参数指纹。任一改变使相关验证过期，并使依赖节点待复核。
5. 桌面、CLI、MCP、导出使用同一投影。仍展示“分析、图表、网页、下载”四项状态；各项附具体缺口。
6. 对本轮 23 项执行一次“导入证据—重新验证—同步状态”，不重做已经完成的远端分析。旧任务缺少新证据时保持“未核验”。

验收：故意换成另一条等长序列的结果，不能通过；修改单个文件后旧核验失效；桌面与 CLI 及导出清单一致；原失败日志仍可追溯。

### C. 原网页、静态图件与附件

1. 统一原生节点和补回结果的归档入口；保存前要求结果标志、关键图表和实际使用的字体就绪。Loading、空白图表、错误页不能判完整。
2. 保存 CSS、嵌套引用、字体、图片、SVG、背景、iframe、当前输入和选择值；路径可移动。对跨域或不可序列化区域保存明确标注的静态图像。
3. 区域截图和整页截图使用独立参数；同时核对截图覆盖范围、关键区域内容，防止“图存在但截错位置”。
4. 原网页与整理静态页分别记录核验范围。静态页通过不能覆盖原网页 `partial`；无原网页不能自动写成“不适用”。
5. 每个适配器声明必需和可选附件。记录期待、生成中、下载中、已完成、已解析、缺失及错误状态。对中断文件保留可恢复记录，完成后原子发布。
6. 大文件流式校验；处理压缩传输时区分网络字节与解压后的文件大小。格式验证及序列关联独立于哈希验证。
7. 离线验收使用新上下文、禁用分析脚本及联网、清空缓存，验证原存档和导出副本。对字体与布局差异定位原因，不统一放宽阈值来消除失败。

验收：本轮四个 partial 网页逐项复验；缺 CSS／字体、相对路径、延迟图表、持续 Loading、空白 Canvas、WebGL、POST 弹窗、下载中断均有正反例；移动至中文及空格路径、重启 Chrome 后仍通过。打开存档不得产生分析请求。

### D. 站点适配器与依赖流程

1. 为高频站点提供明确的 `submit / reconcile / poll / fetch / parse / archive` 生命周期；模型处理页面变体，确定的作业查询和下载走固定逻辑。
2. 优先迁移本轮人工干预最多的 HMMER、ESPript、InterPro、MusiteDeep、SWISS-MODEL／PrankWeb 和 BLAST；随后覆盖本次全部 26 项的验证与状态映射。
3. 表单字段使用语义约束及填写后的读回校验。序列不能进入标题、检索区间、物种或 accession 字段。
4. 同源检索→筛选→MAFFT→ESPript／WebLogo／IQ-TREE，结构建模→PrankWeb，均登记为明确依赖。输入不可变，保存父节点产物指纹。
5. 同源筛选规则、工具版本、随机种子、命令行、模型和阈值统一进入机器可读参数记录；IQ-TREE seed 同时进入结果摘要。
6. 原站出现 CPU 限制、物种不支持、页面接口变更时分型呈现；不能换工具、换物种或把服务报错解释成无命中。

验收：替换上游序列或模型时，仅有关后继节点失效；软件能够说明每张图来自哪一轮、哪份输入；已完成站点作业在模型不可用时仍可查询、下载和验证。

### E. 统一工作区、工具和实际发布版本

1. 增加构建清单，覆盖源码树摘要、前后端和引擎摘要、协议及配方版本。当前工作区有未提交修改，单一 Git commit 不足以标识构建。
2. 桌面连接后台时核对 build ID、引擎路径、工作区规范路径、协议版本；CLI 返回同样信息。不一致时显示具体路径，阻止混用执行。
3. 在执行前验证 Chrome、Python、IQ-TREE 等工具位置和版本；工具缺失时精确提示，不能由分析中途的临时复制掩盖安装问题。
4. 所有修复合入后重建 Windows 软件和安装包；先在独立候选目录验收，再替换正式交付。保留可回退版本和旧任务。
5. 回归运行实际安装／解包产物，而不只运行仓库源码。候选版本在新工作区完成最小真实任务，再导入本轮结果验证兼容性。

验收：桌面、CLI、后台三方指纹一致；实际包包含截图修复；本地工具无需手工补路径；旧任务可读；卸载或升级不得丢失共享工作区成果。

- **PSI-BLAST**：本次原作业返回 CPU usage limit exceeded。软件应正确识别、保存回执并呈现原因，但修复软件不能消除原站资源限制。
